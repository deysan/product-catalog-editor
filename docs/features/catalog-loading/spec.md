# Spec — catalog-loading

> **Glossary:** [CONTEXT](CONTEXT.md).
> **Inputs:** [idea-brief](../../idea-brief.md), [architecture-map](../../architecture-map.md), [roadmap](../../roadmap.md), [ADR-003](../../adr/003-ephemeral-state.md).
> **Source reference:** [DummyJSON Products documentation](https://dummyjson.com/docs/products), перевірено 2026-10-03: підтримує обмеження кількості товарів і містить необхідні поля. Валюту документація не визначає; її не припускаємо.

## 1. Context

Учасник воркшопу потребує першого робочого кроку навчального редактора: переглянути товари й зрозуміти результат завантаження. Зараз застосунок має лише мінімальний екран; функцій каталогу ще немає.

Крок готується до практики послідовного проходження SDD. Тривалість воркшопу не є дедлайном; на цьому етапі створюємо специфікацію без реалізації.

Погоджений підхід: при відкритті екрана автоматично запитувати до 20 перших товарів із DummyJSON і показувати отримані картки, очікування, порожній стан або помилку з ручною повторною спробою. Пошук і локальні зміни належать наступним крокам.

Джерела обсягу — бриф §1, §5, §7 і крок 1 роадмапи. Обмеження реалізації успадковано з карти архітектури та ADR, без нових архітектурних рішень. Розмір S відповідає роадмапі: вводиться один модуль каталогу, без нового серверного API, міграцій і несумісних змін. Кількість PR і тривалість не оцінюємо як зобов’язання.

## 2. Goals

- Дати учаснику воркшопу повний початковий каталог із даними карток, які відповідають джерелу.
- Зробити очікування та невдале завантаження зрозумілими й дозволити відновити перегляд повторною спробою.
- Підготувати каталог і початковий знімок для наступних кроків, не додаючи їхніх дій у поточний екран.

## 3. Non-goals

- Пошук, редагування, видалення й скидання — окремі наступні кроки роадмапи; відповідних елементів керування тут немає.
- Пагінація, сортування, фільтри, детальна сторінка й додаткові товари — працюємо лише з початковим набором.
- Серверна частина, авторизація, серверний запис і збереження між перезавантаженнями — каталог навчальний і живе в пам’яті вкладки.
- Автоматичні повтори, оновлення успішного каталогу, складне оформлення й гарантія доступності зовнішнього джерела — не потрібні для першого робочого кроку.

## 4. User stories

### US-01: Відкрити початковий каталог
**As a** Учасник воркшопу **I want** отримати товари при відкритті екрана **So that** почати перегляд без додаткових дій.

### US-02: Переглянути дані товару
**As a** Учасник воркшопу **I want** бачити фото, назву й ціну кожного товару **So that** розпізнати позицію каталогу.

### US-03: Розуміти очікування завантаження
**As a** Учасник воркшопу **I want** бачити стан очікування **So that** відрізняти його від помилки або готового каталогу.

### US-04: Зрозуміти невдале завантаження
**As a** Учасник воркшопу **I want** бачити зрозуміле повідомлення про помилку **So that** знати, чому товари недоступні.

### US-05: Повторити невдале завантаження
**As a** Учасник воркшопу **I want** вручну повторити спробу **So that** відновити перегляд без перезавантаження сторінки.

## 5. Acceptance criteria

### AC-01 (US-01) — happy
**Given** Учасник воркшопу відкриває застосунок уперше або після перезавантаження сторінки.
**When** джерело надає коректний набір від 1 до 20 товарів.
**Then** завантаження починається автоматично, після завершення видно стільки карток, скільки товарів отримано, у порядку джерела; повідомлень очікування й помилки та кнопки повторної спроби немає.

### AC-02 (US-02) — happy
**Given** каталог успішно завантажено.
**When** Учасник воркшопу переглядає картку.
**Then** видно фото саме цього товару, його повну назву та ціну джерела з двома десятковими знаками без перерахунку, знижки чи припущеної валюти; фото має текстовий опис із назвою товару.

### AC-03 (US-03, US-05) — domain invariant
**Given** початкове завантаження або повторна спроба ще триває.
**When** Учасник воркшопу переглядає екран або намагається повторити спробу знову.
**Then** видно «Завантаження товарів…», карток і попередньої помилки немає; нову спробу неможливо почати до завершення поточної. Кнопка повторної спроби прихована або недоступна.

### AC-04 (US-04) — error
**Given** завантаження завершилося невдачею через мережу, відмову джерела або неможливість прочитати відповідь.
**When** Учасник воркшопу переглядає екран.
**Then** карток і повідомлення очікування немає; видно «Не вдалося завантажити товари. Спробуйте ще раз.» та доступну кнопку «Спробувати ще», без технічного тексту помилки.

### AC-05 (US-04) — domain invariant
**Given** отриманий набір містить понад 20 товарів, повторні ідентифікатори або хоча б один некоректний товар, чи список товарів відсутній або має неправильний формат.
**When** завантаження завершується.
**Then** застосунок не показує частковий чи некоректний каталог; Учасник воркшопу бачить помилку й повторну спробу як у AC-04. Коректний товар має унікальний додатний цілий ідентифікатор, непорожню після усунення крайніх пробілів назву, скінченну невід’ємну числову ціну й адресу фото з протоколом https або http. Зайві поля джерела не впливають на результат.

### AC-06 (US-05) — happy
**Given** видно помилку й доступну повторну спробу.
**When** Учасник воркшопу активує «Спробувати ще».
**Then** починається нове завантаження з очікуванням за AC-03; успіх показує каталог за AC-01 або порожній стан за AC-10, повторна невдача повертає стан AC-04 і дозволяє наступну ручну спробу.

### AC-07 (US-01) — authorization
**Given** Учасник воркшопу не має облікового запису й не виконував вхід.
**When** він відкриває каталог або повторює невдале завантаження.
**Then** перегляд і повторна спроба доступні без входу та перевірки ролей. Негативні сценарії прав доступу не застосовні: каталог публічний, авторизація поза обсягом.

### AC-08 (US-01, US-04) — cross-context
**Given** каталог залежить від зовнішнього джерела й у поточній вкладці ще не завантажений.
**When** джерело недоступне.
**Then** Учасник воркшопу бачить стан AC-04; застосунок не підставляє демонстраційний набір або дані з попередньої сесії. Після відновлення джерела ручна повторна спроба може показати актуальний набір.

### AC-09 (US-02) — error
**Given** каталог успішно завантажено, але фото одного товару не вдалося відобразити.
**When** Учасник воркшопу переглядає картку.
**Then** замість зламаного фото видно «Фото недоступне»; назва, ціна й решта карток залишаються доступними, загальна помилка каталогу не виникає.

### AC-10 (US-01, US-05) — happy
**Given** початкове завантаження або повторна спроба повернула коректний порожній масив товарів.
**When** завантаження завершується.
**Then** Учасник воркшопу бачить «Товарів немає», без карток, повідомлення очікування, помилки й кнопки повторної спроби; автоматичної повторної спроби немає.

## 6. Non-functional requirements

| Aspect | Target | Measurement |
|---|---|---|
| Доступність | 100% активацій retry можливі клавіатурою; повідомлення очікування й помилки доступні допоміжним технологіям; кожне фото має опис | Перевірка семантики, клавіатурного сценарію та текстових описів у компонентних тестах і браузері |
| Конкурентність | Не більше 1 активної спроби завантаження на вкладку; 0 автоматичних повторів | Кероване незавершене завантаження й повторні активації у тестах |
| Адаптивність | 0 горизонтального прокручування екрана на ширинах 320 і 1280 CSS-пікселів, зокрема з довгою назвою | Ручна браузерна перевірка обох ширин |
| Ізоляція перевірок | 0 реальних мережевих звернень у автоматизованих тестах; 100% сценаріїв §5 мають перевірку | Підміна джерела та таблиця Test plan |

Доступність і час відповіді DummyJSON не гарантуються застосунком; окремих SLO, навантажувальних перевірок і штучних затримок не вводимо.

## 6.1 Security / privacy

- **Data classification:** public — демонстраційні товари відкритого джерела.
- **Personal data touched:** none — використовуємо лише ідентифікатор, назву, ціну й фото, без відгуків та контактних даних із повної відповіді.
- **AuthZ/AuthN impact:** немає; перегляд публічний, запису даних немає.
- **Abuse cases:** назва з розміткою відображається як текст; некоректні дані й адреси фото відхиляються за AC-05; повторні активації під час очікування не створюють паралельних завантажень.
- **Security review:** N/A — розмір S, без нової межі доступу та персональних даних.

## 7. Metrics / KPIs

Метрики є критеріями готовності кроку до переходу далі, без аналітики й телеметрії. Baseline — поточний skeleton.

- **Повнота перегляду:** 0 → 3 перевірені обсяги коректного набору (20, менше 20, порожній), кількість карток відповідає отриманим товарам, до завершення перевірки реалізації.
- **Покриття станів:** 0 → 4 перевірені видимі стани (очікування, каталог, порожній каталог, помилка) до завершення перевірки реалізації.
- **Відновлення:** 0 → 3 перевірені результати повторної спроби (каталог, порожній каталог, повторна помилка) до завершення перевірки реалізації.

## 8. Open questions

Немає блокувальних відкритих питань за наведених нижче припущень. Правила пошуку, форми й скидання та дата воркшопу залишаються у відповідних наступних кроках і не блокують цю специфікацію.

## Assumptions / decisions ledger

- Явна вказівка автора: лише специфікація; українська мова; route quick, depth easy; інші функції відкладені. Локальні налаштування SDD не змінено.
- Easy-default: розмір S із роадмапи, один новий модуль; без міграцій, нового серверного API чи несумісних змін. PR і строки не є обіцянкою.
- Підтверджено автором: запитуємо до 20 товарів, менший набір показуємо повністю; порожній масив дає «Товарів немає»; помилки мережі, HTTP або даних дають повідомлення й «Спробувати ще»; недоступне фото замінюємо на «Фото недоступне»; автоматичних повторів немає. Припущення для review: завантаження автоматичне при відкритті, порядок джерела збережено, некоректний набір відхиляється цілком.
- Пропозиції для review: UI-повідомлення українською, назви джерела не перекладаємо; ціна з двома десятковими знаками без позначення валюти, оскільки її не визначено у джерелі.
- Успіх означає перевірені дані каталогу; завантаження самих фото може завершуватися пізніше. Порожній масив є успішним завантаженням без товарів; відсутній або некоректний список є помилкою даних. Порожній каталог і його початковий знімок також містять нуль товарів.
- Межі архітектури: дотримуємося наявних ADR і AGENTS.md. Початковий знімок створюється окремою копією лише після успіху й не мутується; дія reset тут не з’являється. Технічні контракти й розміщення логіки уточнює design.
- Адаптація шаблону: authorization перевіряє публічний доступ, cross-context — залежність від зовнішнього джерела; нових ролей і бізнес-контекстів не вводимо.
- Edits-log: автор змінив «рівно 20, інакше помилка» на «до 20; менше показуємо; порожній масив — Товарів немає» та задав текст кнопки «Спробувати ще». Оновлено §1, AC-01/05/06/10, §7 і Test plan. Решта припущень не є підтвердженням автора.

## Test plan

План для майбутньої реалізації; тести зараз не пишемо. Використовуємо наявні Vitest, React Testing Library і jsdom; ізолюємо store між тестами й підмінюємо fetch.

| AC | Level | Scenario |
|---|---|---|
| AC-01, AC-07 | integration (App / Catalog) | Монтування без входу автоматично завантажує 20 позицій; порядок, кількість і кінцевий стан правильні; нова сесія завантажує заново |
| AC-02 | component | Фото, опис, повна назва й формат ціни відповідають одному товару; довга назва та розмітка лишаються текстом |
| AC-03 | model + integration | Незавершена спроба показує очікування; повторні активації й повторне монтування в межах вкладки не дублюють активне завантаження |
| AC-04, AC-08 | API + model + integration | Мережева помилка, невдала відповідь і нечитабельні дані завершують очікування помилкою та retry без підставного каталогу |
| AC-05 | API + model | Набір понад ліміт, відсутній список, дублікати ідентифікаторів, неправильні або відсутні обов’язкові поля відхиляються цілком; нульова ціна й зайві поля допустимі; після успіху каталог і знімок не ділять змінювані об’єкти |
| AC-06, AC-07 | integration | Retry після помилки веде до каталогу, порожнього стану або нової помилки, не потребує входу; доступний із клавіатури |
| AC-09 | component | Невдале відображення фото показує текстову заміну й зберігає дані картки |
| AC-10, AC-01 | integration | Коректні набори з 0, 1, 19 і 20 товарів: порожній стан або відповідна кількість карток, без автоматичного повторення |

Перед завершенням реалізації: build, відповідні тести й lint, а також браузерна перевірка карток, клавіатури та ширин із §6. На етапі специфікації ці команди перевіряють лише незмінений skeleton.
