# Screens — catalog-search

Канонічний маніфест SCR-01 для tasks, implement і review: стани, видимий вміст, компоненти та взаємодії описані тут повністю. Наступні етапи читають цей документ; окремого дизайн-файлу немає. Це документація майбутнього пошуку, не його реалізація.

## Source

- **Tool:** code із [design-system](../../design-system.md).
- **File:** inline wireframes below — схеми в цьому документі; деградація інструмента не потрібна.
- **Вимоги:** [spec](spec.md) §5–6, [ux-flows](ux-flows.md) §Screen inventory і Platform decisions, [sad](sad.md) §4–6/8, `target_surfaces: [web-frontend]`.
- **Успадкований UI:** [catalog-loading screens](../catalog-loading/screens.md); для поля й результатів пошуку цей маніфест доповнює його вимоги.
- **Контракти:** `contracts/` відсутній; SAD і design-log визначають API-стадію N/A, бо пошук не змінює зовнішній контракт. Error успадковується із catalog-loading; нових контрактних помилок немає.
- **Актуальність:** design-system існує, має пріоритет над історичною згадкою його відсутності в UX. Inventory ще позначає Catalog, ProductCard і RetryButton як NEW, але перші два вже реалізовані, а RetryButton є нативною кнопкою всередині Catalog. Тут це повторне використання тих самих позицій інвентарю.

## Screens

### SCR-01 — Каталог із пошуком

#### Оформлення та доступність

- Перевикористати токени design-system: світлий фон, біла поверхня, основний текст, рамки й контур фокуса; системний шрифт 16px/1.5. Контейнер до 960px, зовнішні відступи 16px, від 640px — 32px. Список `ul`/`li`: одна колонка, від 640px — дві, від 960px — три, проміжок 16px. На 320 і 1280 CSS-пікселях немає горизонтального прокручування.
- Поле на всю доступну ширину контейнера, `min-width: 0`, `box-sizing: border-box`; відстань між label і полем 8px, після поля до результату 16px. Нативний `input type="text"` із пов’язаним видимим `label` «Пошук за назвою», висота щонайменше 44px, відступи 8px 16px, рамка 1px кольору `--color-muted`, радіус 4px. Біле тло, основний текст, успадкований шрифт. Декоративна `--color-border` лишається для карток і блоків стану; рамка поля має забезпечувати контраст щонайменше 3:1 до поверхні.
- `:focus-visible`: чинний контур 3px `--color-focus` із відступом 3px, без обрізання. Tab переводить фокус у поле та з нього; очищення — Ctrl+A/Cmd+A та Backspace/Delete. Поле й фокус зберігаються при переходах між WF-02–WF-05; додаткові submit, кнопка очищення й Escape не потрібні.
- Оновлення від кожної зміни тексту синхронне, без debounce, очікування пошуку чи нової мережевої спроби. `aria-busy` відповідає лише idle/loading і знімається після завершення завантаження. Пошук не змінює його.
- Повідомлення no-match і catalog-empty займають той самий блок стану. У success із картками блок залишається без видимого повідомлення для збереження чинного механізму retry-focus. Повідомлення переносяться; no-match не оформлюється як червона помилка.
- Картки успадковують фото 160px із `object-fit: contain`, `alt` із назвою, повну назву в `h2` та ціну з двома десятковими знаками без валюти. Висота карток рядка однакова, ціна внизу, проміжок після назви щонайменше 8px. Картки не інтерактивні.

#### Переходи та інваріанти

- AC-01/02: зміна тексту переводить між all-products, matches і no-match без підтвердження; порівняння підрядка лише назви без урахування регістру та крайніх пробілів, внутрішні пробіли буквальні.
- AC-03/07: no-match дозволяє змінити або очистити поле; порожній поточний каталог завжди показує catalog-empty. До success пошук прихований.
- AC-04: введення, нуль збігів і очищення змінюють тільки видимість карток. Кількість, порядок і всі поля каталогу та початкового знімка збережені, звернень через пошук немає. Очищення повертає всі поточні товари.
- AC-05: зовнішня локальна зміна актуальних товарів повторно визначає WF-02–WF-05 за збереженим текстом; це не новий стан і не додає UI редагування/видалення. Джерело результату — поточний каталог, не знімок.
- AC-06: усі успішні варіанти доступні без входу чи дозволів; окремого екрана заборони доступу немає.

## Assumptions / decisions ledger

- Розмір XS і route quick прочитані з `.size`/`.route`; tool code із design-system. Мову збережено за сусідніми документами функції.
- Поточний `interview_depth: medium` із `.claude/sdd.local.md`; історичний easy попередніх етапів не є новим override. Один SCR-01 подається на опційне підтвердження; документ лишається draft без явного прийняття.
- Візуальні defaults поля: label над полем, ширина контейнера, нативний text-input і чинні токени/відступи. Placeholder та нові повідомлення не потрібні; правила пошуку й пріоритети станів походять із джерел.
- Self-check: 4/4 — єдина позиція SCR-01 покрита; default, loading, success, обидва empty й error описані, validation явно N/A; усі компоненти в inventory або §New components; кожне відмінне компонування має inline wireframe.
