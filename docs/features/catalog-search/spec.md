# Spec — catalog-search

> **Glossary:** [CONTEXT](CONTEXT.md).
> **Reference docs:** [idea-brief](../../idea-brief.md), [architecture-map](../../architecture-map.md), [roadmap](../../roadmap.md), [catalog-loading](../catalog-loading/spec.md).
> Route **quick**, depth **easy**. Лише специфікація; реалізація й наступні етапи не входять у цей запуск. Мову збережено відповідно до наявних документів каталогу.

## 1. Context

Учаснику воркшопу потрібно знаходити товари за назвою в уже завантаженому каталозі, не переглядаючи вручну всі картки. Каталог містить до 20 товарів; пошук охоплює лише поточний набір у пам’яті вкладки.

Завантаження й стани завершено окремим кроком catalog-loading. Пошук є наступним навчальним кроком роадмапи перед редагуванням, видаленням і скиданням.

Обраний підхід — локальний пошук підрядка назви без урахування регістру та крайніх пробілів запиту. Порожній запит повертає весь поточний каталог; відсутність збігів має зрозуміле повідомлення. Пошук змінює тільки видимий список.

Вихідна вимога автора: «за назвою, без урахування регістру; порожній запит показує весь каталог; якщо збігів немає — показуємо відповідне повідомлення. Нових запитів до API не робимо. Пошук не змінює товари або початковий знімок».

## 2. Goals

- Знаходити поточні товари за частиною назви незалежно від регістру.
- Однозначно розрізняти результати пошуку, відсутність збігів і порожній каталог.
- Зберігати дані каталогу й початкового знімка та працювати без додаткового завантаження.

### Constraints

Зберігаємо один екран та наявні стани завантаження. За картою архітектури запит є локальним станом компонента, видимий список обчислюється з актуального каталогу й не зберігається дублем у store. Нових залежностей, зовнішніх контрактів або міграцій немає.

## 3. Non-goals

- Серверний пошук і завантаження додаткових товарів — працюємо з уже отриманим каталогом.
- Пошук за іншими полями, приблизні збіги, сортування й підсвічування — достатньо підрядка назви.
- Реалізація редагування, видалення й скидання — це окремі кроки; тут визначена лише сумісність із поточними даними.
- Збереження запиту між перезавантаженнями й авторизація — стан тимчасовий, навчальний екран доступний без входу.

## 4. User stories

### US-01: Знайти товар за назвою
**As a** Учасник воркшопу **I want** вводити частину назви **So that** бачити лише відповідні товари.

### US-02: Повернути весь каталог
**As a** Учасник воркшопу **I want** очистити пошуковий запит **So that** знову бачити всі поточні товари.

### US-03: Зрозуміти відсутність збігів
**As a** Учасник воркшопу **I want** бачити повідомлення за відсутності збігів **So that** змінити запит і продовжити пошук.

### US-04: Зберегти товари під час пошуку
**As a** Учасник воркшопу **I want** шукати локально без зміни даних **So that** не втратити товари й початковий знімок.

### US-05: Шукати у поточному каталозі
**As a** Учасник воркшопу **I want** результати за актуальними назвами **So that** бачити відповідність поточному стану каталогу.

## 5. Acceptance criteria

### AC-01 (US-01) — happy
**Given** каталог успішно завантажено й містить «Apple Juice», «Pineapple» та «Milk».
**When** Учасник воркшопу вводить «aPpLe» у поле «Пошук за назвою».
**Then** без окремого підтвердження видно картки «Apple Juice» та «Pineapple» в порядку каталогу; «Milk» приховано. Пошук перевіряє тільки назву, а не ціну чи інші поля.

### AC-02 (US-01, US-02) — happy
**Given** каталог успішно завантажено.
**When** Учасник воркшопу вводить «  apple  », очищає поле або вводить лише пробіли.
**Then** крайні пробіли ігноруються: перший запит рівнозначний «apple», два останні показують усі поточні товари. Внутрішні пробіли та інші символи порівнюються буквально; приблизних збігів немає.

### AC-03 (US-03) — error
**Given** непорожній каталог успішно завантажено.
**When** пошуковий запит не має жодного збігу.
**Then** карток немає, видно «За вашим запитом товарів не знайдено». Поле залишається доступним; зміна або очищення запиту відновлює відповідний список. Це не помилка завантаження: повторна спроба не з’являється.

### AC-04 (US-04) — domain invariant
**Given** каталог і початковий знімок уже завантажено.
**When** Учасник воркшопу вводить, змінює та очищає запит, зокрема отримує нуль збігів.
**Then** кількість, порядок та всі поля товарів у каталозі й початковому знімку залишаються незмінними; очищення повертає весь поточний каталог. Жодна пошукова дія не звертається до зовнішнього джерела.

### AC-05 (US-05) — cross-context
**Given** каталог згодом змінено локально іншою функцією, а пошуковий запит залишається введеним.
**When** змінюється актуальна назва чи склад каталогу.
**Then** видимий список одразу відповідає поточним назвам і товарам, а не початковому знімку: перейменований товар перевіряється за новою назвою, відсутній у каталозі товар не показується. Критерій не додає дій редагування чи видалення в цей крок.

### AC-06 (US-01) — authorization
**Given** Учасник воркшопу відкрив навчальний застосунок без входу в обліковий запис і каталог успішно завантажено.
**When** він користується пошуком.
**Then** пошук доступний без реєстрації, входу або додаткових дозволів. Заборона доступу N/A: у продукті немає ролей чи захищених каталогів.

### AC-07 (US-03, US-05) — cross-context
**Given** початкове завантаження очікується, завершилося помилкою або успішно повернуло порожній каталог.
**When** Учасник воркшопу переглядає екран.
**Then** до успіху поле пошуку не показується й повідомлення про відсутність збігів не замінює очікування або помилку з повторною спробою. Після успішного порожнього завантаження поле доступне, а за будь-якого запиту видно «Товарів немає» замість повідомлення про відсутність збігів.

## 6. Non-functional requirements

| Aspect | Target | Measurement |
|---|---|---|
| Обсяг | Коректний результат для 0–20 товарів | Перевірки порожнього, малого й граничного наборів |
| Взаємодія | 0 додаткових дій після введення тексту для оновлення списку | Компонентна перевірка введення без submit |
| Мережа | 0 додаткових звернень через пошук | Лічильник підміненого fetch до й після пошукових дій |
| Цілісність | 0 змін каталогу та початкового знімка | Порівняння всіх полів і порядку до й після пошуку |
| Доступність | 1 видима пов’язана мітка поля; 100% пошукових дій доступні клавіатурою | Перевірка семантики й ручне введення та очищення |

Серверні throughput та availability N/A: функція локальна, нових операцій сервера немає.

## 6.1 Security / privacy

- **Data classification:** public — завантажені товари є публічними даними джерела.
- **Personal data touched:** none — нові персональні поля не додаються; запит не надсилається й не зберігається між перезавантаженнями.
- **AuthZ/AuthN impact:** none — пошук доступний усім відвідувачам навчального екрана.
- **Abuse cases:** текст із розміткою, символами шаблонів або лапками обробляється як буквальний текст; він не виконується як код і не змінює товари. Повторне введення не створює мережевих звернень. Запит не передається зовнішнім сервісам чи аналітиці.
- **Security review:** N/A — немає нової межі доступу, персональних даних або зовнішньої передачі.

## 7. Metrics / KPIs

Метрики приймання навчальної функції, без телеметрії; перевірити до завершення її реалізації.

- **Коректність пошуку** — baseline: пошуку немає; target: 100% сценаріїв AC-01–AC-03 проходять.
- **Незмінність даних і мережі** — baseline: пошуку немає; target: 0 змінених полів та 0 додаткових звернень у AC-04.
- **Сумісність зі станами каталогу** — baseline: пошук не інтегровано; target: 100% сценаріїв AC-05–AC-07 проходять.

## 8. Open questions

Немає відкритих питань. Автор підтвердив пошук підрядка та ігнорування крайніх пробілів.

## Assumptions / edits log

- XS: одна невелика зміна існуючого модуля, без нового API, міграцій і breaking changes; очікувано один PR, до одного робочого дня. Це оцінка масштабу, не обіцянка строку. Route quick і depth easy задані автором.
- Регістр, порожній запит, повідомлення без збігів, відсутність нових запитів і незмінність даних — явні вимоги автора.
- Підрядок та ігнорування крайніх пробілів підтверджено автором у цьому запуску; D1 роадмапи закрито. Внутрішні пробіли враховуються буквально.
- Поле доступне після успішного завантаження, включно з порожнім каталогом; початковий запит порожній. Нові повідомлення українською відповідно до наявного екрана.
- Error покрито відсутністю збігів як негативним результатом, authorization — явно відкритим доступом; не вигадуємо валідаційних помилок чи ролей.
- Ideation suite пропущено для easy; джерела обмежено документами, вказаними автором, і словником та специфікацією попереднього кроку.

## Test plan

Узгоджено автором у запуску `plan-tests`: прийнято запропоновані рівні для всіх AC та стратегію перевірки. Розмір XS, route quick — план inline; окремий test-plan.md не створюємо. Тестовий код пишеться на етапі implement.

### Levels

- `unit` — чисте правило фільтрації без I/O.
- `component` — відображення та взаємодія каталогу з реальним store в ізольованому оточенні. Store не підмінюється.
- `integration`, `contract`, `e2e`, `load`, `visual-regression`, `e2e-through-UI` не обрані як автоматизовані рівні цього кроку. Нової зовнішньої залежності, контракту або сховища немає; браузерна перевірка нижче ручна й не замінює автоматизоване покриття AC.

### Edge cases / error paths

- AC-03 — окремий негативний сценарій; після іншого запиту без збігів повідомлення зберігається, після збігу або очищення список відновлюється.
- AC-06 — окремий сценарій відкритого доступу. Відмову в доступі не вигадуємо: ролей і захищених каталогів немає.
- AC-07 — окремі перевірки початкового очікування, помилки з повтором та успішного порожнього каталогу, за станами WF-01, WF-05, WF-06 зі screens.md.
- AC-02, §6.1 — кілька внутрішніх пробілів, лапки, символи шаблонів та текст із розміткою порівнюються буквально. Текст не виконується й не створює помилку поля; тестова назва зі спецсимволами дозволяє перевірити буквальний збіг.
- AC-05 — перейменування як у збіг, так і зі збігу; видалення останнього збігу та перехід до порожнього поточного каталогу при незмінному запиті. Поточні дані та початковий знімок навмисно різні.
- §6 — набори з 0, 3 та 20 товарів; кілька збігів, один збіг і жодного. Не додаємо поведінки поза визначеним обсягом.

### Test data / cleanup

- Фікстури відповідають Product: числовий id, title, price, thumbnail. Базовий набір — «Apple Juice», «Pineapple», «Milk»; додаткові набори перевіряють буквальні символи, порядок і верхню межу 20 товарів.
- Перед кожним компонентним тестом створювати окремі копії поточного каталогу й початкового знімка, задавати потрібний статус. Для AC-04 зберігати незалежні глибокі копії перед пошуком і порівнювати всі поля після кожної дії.
- Зовнішній fetch підмінювати детермінованими відповідями; для loading використовувати керовано незавершену відповідь, для error — контрольований збій. Реальна мережа не потрібна. Лічильник для AC-04 фіксувати після завершення початкового завантаження, щоб відокремити його від пошуку.
- Межа очищення — кожен тест: демонтувати UI, відновити початковий стан store та підмінену мережеву функцію; завершити керовані асинхронні операції. Unit-фікстури створювати незалежно для кожного тесту.
- Integration dependency: N/A — немає власної БД, кешу, черги чи backend; контейнер не потрібен. Компонентні тести використовують реальний store у пам’яті, а підміна fetch ізолює зовнішнє джерело відповідно до правил проєкту.

### NFR validation (load)

N/A стосується числових вимог до навантаження: §6 не задає throughput, тривалості навантаження чи порога latency. ### Accessibility / browser verification

Компонентно перевірити видиму пов’язану мітку «Пошук за назвою», доступне ім’я поля, збереження поля та фокуса під час зміни результатів, окремі семантичні повідомлення результату й помилки завантаження за screens.md.
